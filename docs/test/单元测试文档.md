# 单元测试文档

本文档记录 `sales-dg` 项目的 48 个单元测试，覆盖 LLM 端点 URL、配置密钥脱敏、流式文本合并、ASR 标点恢复、Agent 上下文管理、本地会话分析与 AI 回复过滤、ASR 后端分派七个方面。

> **测试代码位置**：实际测试源码位于 `server/tests/`（本目录 `docs/test/` 仅存放说明文档）。
> **依赖清单**：`server/requirements-test.txt`（仅轻量依赖，不含 torch / speechbrain / funasr 等重型库）。

## 2. 运行方式

### 2.1 本机虚拟环境（推荐，最快）

```bash
cd server
python3 -m venv /tmp/sdg-test-venv
/tmp/sdg-test-venv/bin/pip install -r requirements-test.txt
/tmp/sdg-test-venv/bin/python -m unittest discover -s tests -t . -v
```

### 2.2 开发容器内

`docker-compose.yml` 已将 `./server/tests` 挂载到 `/app/tests`：

```bash
docker compose up -d
docker exec ai-meeting-assistant-server \
  sh -c 'cd /app && python3 -m unittest discover -s tests -t . -v'
```

### 2.3 CI

`.github/workflows/ci.yml` 的 `backend` 任务在每次 push / PR 时自动安装 `requirements-test.txt` 并执行：

```bash
python -m unittest discover -s tests -t . -v
```

### 2.4 关于 `-t .` 参数

必须带 `-t .`（top-level directory），使 `tests/__init__.py` 在导入测试模块前执行。该文件将环境变量 `DATA_DIR` 指向系统临时目录：

```python
os.environ.setdefault("DATA_DIR", os.path.join(tempfile.gettempdir(), "sales-dg-test-data"))
```

因为 `app.services.storage` 在模块导入时就会创建 `data_dir` 下的目录，若不隔离，非 root 环境（如 CI）会因无 `/app` 写权限而失败。

## 3. 测试用例明细

### 3.1 `test_llm_url.py` — LLM 端点 URL 归一化（5 个）

验证 `llm_client.api_url()` 根据 `llm_base_url` 与 `llm_api_type` 推导完整端点，且不重复拼接路径。此测试针对已修复的「OCI Responses URL 被重复追加 `/v1/responses`」缺陷。

| 方法 | 验证点 | 关键断言 |
| --- | --- | --- |
| `test_host_only_appends_version_and_endpoint` | 仅主机的 URL 追加版本与端点 | `https://api.deepseek.com` + chat → `.../v1/chat/completions`；`https://api.openai.com` + responses → `.../v1/responses` |
| `test_version_only_appends_endpoint` | 以 `/v1` 结尾时只追加端点 | `https://host/v1` + chat → `.../v1/chat/completions`；+ responses → `.../v1/responses` |
| `test_full_endpoint_not_duplicated` | 已是完整端点时原样返回 | `.../v1/chat/completions`、`.../v1/responses` 不再重复追加 |
| `test_oci_full_action_path_not_duplicated` | OCI 完整 action 路径不被破坏 | `.../20231130/actions/v1/responses` 原样返回（回归测试） |
| `test_trailing_slash_is_stripped` | 尾部斜杠被去除 | `https://api.deepseek.com/` → `https://api.deepseek.com/v1/chat/completions` |

### 3.2 `test_config_view.py` — API Key 脱敏（5 个）

验证 `mask_config()` 与 `unmask_api_key()`，确保 GET 接口不回显明文密钥，PUT / 测试接口能将掩码哨兵还原为真实密钥。

| 方法 | 验证点 | 关键断言 |
| --- | --- | --- |
| `test_mask_hides_saved_key` | 已存密钥被替换为掩码 | `mask_config(key="sk-real-secret").llm_api_key == "__MASKED__"`；原对象未被修改 |
| `test_empty_key_unchanged` | 空密钥保持不变 | `mask_config(key="")` 仍为空字符串 |
| `test_mask_sentinel_restores_saved_key` | 掩码哨兵还原真实密钥 | patch `runtime_config.get` 返回已存密钥；还原后 key 为真实值，且其它字段（如 `llm_model`）保留 |
| `test_new_key_is_kept` | 新密钥直接保留 | 传入 `sk-new-key` 不被覆盖 |
| `test_empty_key_is_kept_for_clear` | 空密钥保留用于清除 | 传入空字符串保持为空，实现「清空密钥」语义 |

### 3.3 `test_text_merge.py` — 流式 ASR 文本合并（6 个）

验证 `merge_stream_text()` 对 FunASR partial 结果做去重拼接，避免叠字。合并规则：新文本为空返回原文本；完全相同或为后缀则不变；为新文本包含原文本则扩展；存在 ≥2 字符重叠则合并去重；否则直接拼接。

| 方法 | 验证点 | 关键断言 |
| --- | --- | --- |
| `test_empty_inputs` | 空输入处理 | `("", "你好")→"你好"`；`("你好", "")→"你好"`；`("","")→""` |
| `test_incoming_extends_current` | 新文本扩展原文本 | `("我们","我们的")→"我们的"` |
| `test_incoming_already_contained` | 新文本已包含则不重复 | `("你好世界","世界")→"你好世界"`；`("你好","你好")→"你好"` |
| `test_overlap_merges_without_duplicate` | 重叠部分合并去重 | `("线索跟进不","跟进不及时")→"线索跟进不及时"` |
| `test_no_overlap_appends` | 无重叠直接拼接 | `("你好","世界")→"你好世界"` |
| `test_single_char_overlap_not_treated_as_overlap` | 单字不算重叠，保护合法叠字 | `("人","人们")→"人们"`；`("各","各位")→"各位"` |

### 3.4 `test_punctuation.py` — ASR final 文本标点恢复（8 个）

验证 `restore_punctuation()` 对 ASR final 文本做轻量本地标点恢复，不依赖本地 LLM 或额外模型。

| 方法 | 验证点 | 关键断言 |
| --- | --- | --- |
| `test_adds_period_for_statement` | 陈述句补句号 | `"我们现在客户线索跟进不及时" → "我们现在客户线索跟进不及时。"` |
| `test_adds_question_mark_for_question` | 疑问句补问号 | `"你们这个系统能不能和我们CRM打通" → "你们这个系统能不能和我们CRM打通？"` |
| `test_keeps_existing_sentence_end` | 已有句末标点不重复 | `"这个问题可以理解。"`、`"你们支持吗？"` 原样保留 |
| `test_inserts_comma_before_connector` | 连接词前补逗号 | `"复杂但是希望" → "复杂，但是希望"` |
| `test_does_not_duplicate_commas_when_punctuation_exists` | 已有标点时不重复插入逗号 | 含 `，但是` 的文本只补句末标点 |
| `test_empty_text` | 空文本处理 | 空字符串或空白返回空字符串 |
| `test_splits_long_clause_with_fixed_rule` | 固定规则切分过长无标点分句 | 长句中插入逗号并补句末标点 |
| `test_fixed_rule_is_deterministic` | 规则标点不再受敏感度参数影响 | 同一输入多次输出一致 |

### 3.5 `test_context_manager.py` — Agent 上下文与记忆（5 个）

验证 `ContextManager` 的问题识别规则、关键词命中、去重上限，以及结构化记忆提取与短期上下文条数限制。

| 方法 | 验证点 | 关键断言 |

| `test_is_question` | 问题识别 | `"这个怎么操作？"`、`"能否提供报价"` 为真；`"我们下周安排演示"` 为假 |

## 4. 设计要点

- **零重型依赖**：ASR 分派测试通过 patch `app.services.asr_dispatch._transcribe_with_faster_whisper` 与 `_transcribe_with_funasr` 两个辅助函数，配合分派模块内的惰性导入，避免加载 numpy / torch / speechbrain / funasr。因此 CI 只需安装轻量依赖。
- **无副作用**：涉及配置的测试用 `patch` 替换 `runtime_config.get`；涉及存储的测试通过 `DATA_DIR` 隔离到临时目录；记忆提取以 `save=False` 执行，均不改动真实数据。
- **回归导向**：`test_oci_full_action_path_not_duplicated` 直接针对生产环境中 OCI Responses URL 被重复拼接的高风险缺陷；脱敏测试针对 API Key 明文回显问题。
- **本地分析，无本地 LLM**：会话分析全部基于关键词规则与打分（`UtteranceAnalysis`），AI 回复触发条件为「指定参会人 + 本地判断为问题」；说明/示例/解释内容只写入 `context_notes` / `key_facts`，通过 `format_context_for_llm()` 注入远程 LLM 的提示词。
